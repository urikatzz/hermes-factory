# Game audio in the Factory (Audio type, Audio Director, Sound Designer, audio-reviewer)

## Intent and approved direction

Audio is made by the Factory the same way game art is (`2026-10-26-game-art-factory-design.md`):

- **Music:** Suno, generated by the user. Suno has no public API.
  - The Factory writes cue sheets and Suno prompts.
  - The user generates the tracks on Suno's website and drops the files into the repo.
  - A later task processes the files.
- **Sound effects:** a built-in sfxr-style synthesizer. It is free, deterministic and needs no key. There is no ElevenLabs key.
- **Formats:**
  - Music: OGG Vorbis.
  - Sound effects: WAV, 16-bit PCM.
- **Factory changes:** a new task type **Audio** with a default **Game Audio** template.

This document does not authorize Git commits or pushes.

## Tools available

- ffmpeg is at `/opt/homebrew/bin/ffmpeg`. It has the `vorbis` encoder (native, experimental, so it needs `-strict -2`) and `loudnorm`. The plan checks whether `libvorbis` is present and prefers it.
- WAV is read and written with the Python standard library (`wave`). ffmpeg is used only for decoding MP3/OGG, measuring loudness and encoding OGG.

## Sound bible (`audio/style/`)

- **`AUDIO.md`:** numbered rules, for example `**A1** (blocking) UI sounds are short and never harsh`.
- **`audio.json`:** version 1 plus a list of classes. Each class has:
  - `name` and `kind`, which is `music` or `sfx`;
  - `match`, a list of globs;
  - `format`: `ogg` or `wav`;
  - `sample_rate`, for example 44100 or 48000;
  - `channels`: 1 or 2;
  - `duration_s`, a range `[min, max]`;
  - `loudness_lufs`: a target plus a tolerance, for example `{target: -16, tolerance: 2}` for music;
  - `peak_dbfs_max`, for example -1.0;
  - `loop` (true or false);
  - `silence_max_ms` at the start and end;
  - `rules`: rule IDs.
- A missing or invalid bible blocks asset tasks, as with art. A style task creates the bible, and the user approves it by accepting that delivery.

## Task kinds (decided by the Audio Director from the prompt)

1. **Style:** writes `audio/style/` (the bible).
2. **SFX:**
   - The plan lists each effect with its target path, class and a recipe JSON spec. The spec sets:
     - wave (square, saw, sine, triangle or noise);
     - start and end frequency, plus slide;
     - attack, sustain and decay;
     - vibrato;
     - arpeggio;
     - duty;
     - low-pass and high-pass filters;
     - volume;
     - seed.
   - The Sound Designer writes `audio/recipes/<name>.json` and renders it to WAV.
3. **Music cues:**
   - The plan lists each cue with a mood, BPM, length, loop flag, Suno style tags and lyrics or instrumental.
   - The Sound Designer writes `audio/cues/<name>.md`, which holds the copy-ready Suno prompt plus the target file name.
   - It does not produce audio. The delivery tells the user to save the Suno results as `audio/incoming/<name>.(mp3|wav|ogg)`.
4. **Music import:**
   - Covers the cues whose files exist in `audio/incoming/`.
   - The Sound Designer decodes each file, trims leading and trailing silence, and for looping cues finds a loop point at a zero crossing on a bar boundary with a short crossfade.
   - It then loudness-normalizes the file to the class target and encodes OGG to the class path.
   - Cues without an incoming file are listed as `missing` in the metadata. A missing file is not a failure. The criteria cover only the files present.

## audio-production skill (`~/.hermes/factory-skills/worker/audio-production/`)

- **`sfx_synth.py <recipe.json> <out.wav>`**
  - Standard library only.
  - Deterministic for the same recipe and seed.
  - Clamps output to the bible's peak limit.
- **`music_process.py <in> <out.ogg> --class <name> --bible audio/style/audio.json [--loop]`**
  - Uses ffmpeg for decoding, `loudnorm` (two pass) and encoding.
  - The trimming and loop search are Python, run on 16-bit PCM decoded by ffmpeg.
- **`audio_lint.py`** (in audio-review, shared). The writer runs it before completing.

Completion metadata adds:
- `assets`: a list of `{path, kind, route: "synth"|"suno", recipe|cue}`.
- `missing`: cues that have no file yet.

**Repair:**
- The Sound Designer changes only the recipes or processing parameters of the assets named in the findings.
- It never edits `audio/style/` outside a style task.
- It never edits `audio/incoming/`, which belongs to the user.

## audio-reviewer and lint

`audio_lint.py <repo> [paths] --out DIR [--fail-on-blocking]` measures each asset against its class:

- **Format:** container, codec, sample rate, channels. A mismatch is HIGH, and an unreadable file is a BLOCKER.
- **Duration:** outside the range is HIGH.
- **Peak and clipping:** a peak above the limit is HIGH. Clipping, meaning three or more consecutive full-scale samples, is HIGH.
- **Loudness:** integrated LUFS from ffmpeg `ebur128`. Outside the tolerance is MEDIUM, and more than twice the tolerance is HIGH.
- **Silence:** leading or trailing silence above `silence_max_ms` is MEDIUM.
- **Loop seam:** for looping classes, the jump between the last and first sample, plus the RMS mismatch across the seam. A click is HIGH.
- **DC offset:** MEDIUM.
- **Unclassified file:** MEDIUM.
- **Stale cue:** a cue sheet without a delivered file is LOW, reported only.

**Output:**
- `lint.json`.
- A waveform and spectrogram PNG per asset, from ffmpeg `showwavespic` and `showspectrumpic`, so a reviewer with vision can inspect the shape if needed.

**The reviewer:**
- It cannot listen. Its judgment is based on measurements.
- It checks each asset against its recipe or cue and the AUDIO.md rules. For example: a "short UI click" that runs 1.2 s; a recipe that does not match the described sound, such as a "jump" with a falling pitch; a cue's BPM or mood tags that contradict the brief.
- Findings use the same F-line format and severities as art-review. A finding on a non-blocking rule is at most MEDIUM.
- With no audio in the manifest, it completes with `audio_surface: "none"`.

## Audio type and Game Audio template

`TASK_TYPES` gains `audio` in every place art was added, with the prefix `AUD`.

The Game Audio preset is seeded by a migration, following the game-art pattern (revision bump, template plus type default):

| Stage | Profile |
|---|---|
| Prepare | audio-director |
| Implement | sound-designer |
| Review | audio-reviewer, claude-reviewer |
| Verify | verifier (runs the audio lint gate in its instructions) |
| Repair | sound-designer, max 2 cycles |

`audio-reviewer` also gets the `review` capability, so any template may include it.

## Rollout and safety

The rollout repeats the game-art rollout:

1. Back up the files the rollout touches.
2. Build and test in `artifacts/game-audio-2026-11-06/build/`.
3. Stop the dashboard and pause claims.
4. Apply the patches and run the migration.
5. Re-bundle the plugin into all homes.
6. Add the profiles and roster entries.
7. Restart the gateway and the dashboard, and run the install checker.

Gateway and update caveats are the same as for art: run `hermes gateway status` after every hermes CLI call.

**Rollback:**
- Restore from the backup.
- Run the reverse migration, which archives the Game Audio template and removes the type default.

## Validation

- Unit tests:
  - the synthesizer: determinism, envelope length, peak clamp, every wave type;
  - music processing, on generated tones through real ffmpeg: trimming, loop seam, loudness within 0.5 LU, OGG output;
  - the lint, on a sample repo with one good and one bad asset per check;
  - the Factory type, template and migration, mirroring `tests/factory_art_type`.
- The Factory install check is extended to cover audio.
- One real end-to-end SFX task and one music-cues task on a sample repo, with the user's go-ahead. A music-import task follows after the user supplies one Suno file.

## Out of scope

- Automatic Suno generation.
- Voice and dialogue.
- Adaptive or layered music.
- Engine import settings.
- Listening-based quality judgment.
